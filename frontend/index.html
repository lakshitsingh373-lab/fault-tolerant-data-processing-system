How dedup works here

Each event is fingerprinted from its normalized client + metric + amount + timestamp. That hash has a UNIQUE constraint in the database. Resubmitting the exact same event — whether by accident, retry, or on purpose — is caught as a duplicate and never double-counted, with no reliance on a client-supplied event ID.
